例如，在上面的 UI 中我们用到了：

- [background-color](/docs/background-color)、[border-radius](/docs/border-radius) 与 [box-shadow](/docs/box-shadow) 工具类（`bg-white`、`rounded-xl` 与 `shadow-lg`）控制卡片外观

- [gap](/docs/gap) 工具类（`gap-x-4`）处理 logo 与文本之间的间距
- [font-size](/docs/font-size)、[color](/docs/text-color) 与 [font-weight](/docs/font-weight) 工具类（`text-xl`、`text-black`、`font-medium` 等）设置卡片文本样式

这种写法与许多传统最佳实践相违背，但你一旦尝试就会发现一些非常重要的好处：

- **完成得更快** —— 你不需要再花时间想类名、思考选择器，也不必在 HTML 与 CSS 文件之间反复切换，设计很快就能搭起来。
- **改起来更安心** —— 给元素增删一个工具类只会影响该元素，不必担心会意外破坏另一处使用同一段 CSS 的页面。
- **维护老项目更容易** —— 想改样式只需在项目中找到对应元素并修改类名，而不必费力回忆半年没碰过的自定义 CSS 怎么运作。
- **代码可移植性更好** —— 由于结构和样式都写在同一个地方，你可以很轻松地复制粘贴整段 UI，甚至跨项目复用。
- **CSS 不再无止境地增长** —— 工具类天然可复用，CSS 不会再随着项目新增功能而线性膨胀。

这些好处在小项目里就已经很明显，对于长期迭代的大型团队项目则更加宝贵。

### 为什么不直接用内联样式？

许多人面对这种写法的第一反应是："这不就是内联样式吗？"某种意义上确实如此——你是在直接给元素应用样式，而不是赋一个类名再去定义那个类。

但相比内联样式，工具类有许多重要优势，例如：

- **在约束中设计** —— 内联样式里每一个值都是魔法数字。工具类则让你从一个[预定义的设计系统](/docs/theme)中挑选样式，从而更容易构建视觉一致的 UI。
- **hover、focus 等状态** —— 内联样式无法针对 hover 或 focus 等状态，而 Tailwind 的[状态变体](/docs/hover-focus-and-other-states)让你用工具类就能轻松设置这些状态的样式。
- **媒体查询** —— 内联样式无法使用媒体查询，但你可以用 Tailwind 的[响应式变体](/docs/responsive-design)轻松构建完全响应式的界面。

## 用工具类思考

### 设置 hover 与 focus 状态样式

要为 hover、focus 等状态设置样式，只需在工具类前加上对应状态前缀，例如 `hover:bg-sky-700`：

<Figure hint="把鼠标悬停在按钮上观察背景色变化">

<Example>
  {
    <div className="grid place-items-center">
      <button className="rounded-full bg-sky-500 px-5 py-2 text-sm leading-5 font-semibold text-white hover:bg-sky-700">
        Save changes
      </button>
    </div>
  }
</Example>

```html
<!-- [!code word:hover\:bg-sky-700] -->
<button class="bg-sky-500 hover:bg-sky-700 ...">Save changes</button>
```

</Figure>

这些前缀在 Tailwind 中称为[变体](/docs/hover-focus-and-other-states)，仅当变体条件匹配时才会应用工具类的样式。

`hover:bg-sky-700` 类生成的 CSS 大致如下：

```css
/* [!code filename: 生成的 CSS] */
.hover\:bg-sky-700 {
  &:hover {
    background-color: var(--color-sky-700);
  }
}
```

注意这个类除非元素被悬停，否则什么都不做。它的_唯一_职责就是提供 hover 样式，再无其他。

这与传统 CSS 写法不同，在传统写法中通常一个类就要负责多个状态的样式：

```html
/* [!code filename:HTML] */
<button class="btn">Save changes</button>

<style>
  .btn {
    background-color: var(--color-sky-500);
    &:hover {
      background-color: var(--color-sky-700);
    }
  }
</style>
```

你甚至可以在 Tailwind 中堆叠变体，让样式仅在多个条件同时满足时才生效，比如组合 `hover:` 与 `disabled:`：

```html
<!-- [!code classes:disabled:hover:bg-sky-500] -->
<button class="bg-sky-500 disabled:hover:bg-sky-500 ...">Save changes</button>
```

更多内容参见 [hover、focus 等状态](/docs/hover-focus-and-other-states)文档。

### 使用类组合

在 Tailwind 中，你常常会使用多个类共同构建一个 CSS 属性的值，例如给一个元素叠加多个滤镜：

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:blur-sm,grayscale] -->
<div class="blur-sm grayscale">
  <!-- ... -->
</div>
```

这两种效果都依赖 CSS 的 `filter` 属性，因此 Tailwind 借助 CSS 变量让它们可以组合：

```css
/* [!code filename:生成的 CSS] */
.blur-sm {
  --tw-blur: blur(var(--blur-sm));
  filter: var(--tw-blur,) var(--tw-brightness,) var(--tw-grayscale,);
}
.grayscale {
  --tw-grayscale: grayscale(100%);
  filter: var(--tw-blur,) var(--tw-brightness,) var(--tw-grayscale,);
}
```

上面生成的 CSS 略作了简化，关键在于：每个工具类只设置自己负责的那段效果对应的 CSS 变量，而 `filter` 属性会读取所有这些变量，未设置的变量则回退为空。

Tailwind 在[渐变](/docs/background-image#adding-a-linear-gradient)、[阴影颜色](/docs/box-shadow#setting-the-shadow-color)、[变换](/docs/translate)等场景也用了同样的方式。

### 使用任意值

Tailwind 中的许多工具类由[主题变量](/docs/theme)驱动，例如 `bg-blue-500`、`text-xl`、`shadow-md`，它们映射到你底层的调色板、字号刻度和阴影。

当你需要使用主题之外的一次性数值时，可以用方括号语法指定任意值：

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:bg-[#316ff6]] -->
<!-- prettier-ignore -->
<button class="bg-[#316ff6] ...">
  Sign in with Facebook
</button>
```

这适用于色板之外的一次性颜色（_比如上面的 Facebook 蓝_），也适用于复杂的一次性值，例如非常具体的网格：

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:grid-cols-[24rem_2.5rem_minmax(0,1fr)]] -->
<div class="grid grid-cols-[24rem_2.5rem_minmax(0,1fr)]">
  <!-- ... -->
</div>
```

也适用于即便使用主题值仍需要 `calc()` 等 CSS 特性的场景：

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:max-h-[calc(100dvh-(--spacing(6)))]] -->
<div class="max-h-[calc(100dvh-(--spacing(6)))]">
  <!-- ... -->
</div>
```

甚至还有用于生成完全任意 CSS（含任意属性名）的语法，对设置 CSS 变量很有用：

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:[--gutter-width:1rem],lg:[--gutter-width:2rem]] -->
<div class="[--gutter-width:1rem] lg:[--gutter-width:2rem]">
  <!-- ... -->
</div>
```

更多内容参见[使用任意值](/docs/adding-custom-styles#using-arbitrary-values)文档。

#### 它到底是怎么工作的？

Tailwind CSS 不是像其他 CSS 框架那样的一份庞大的静态样式表——它会在编译 CSS 时根据你实际用到的类按需生成 CSS。

它通过扫描项目中所有文件，寻找一切看起来像类名的符号来实现：

```jsx
// [!code filename:Button.jsx]
// [!code word:px-4]
// [!code word:py-2]
// [!code word:rounded-md]
// [!code word:text-base]
// [!code word:px-5]
// [!code word:py-3]
// [!code word:rounded-lg]
// [!code word:text-lg]
// [!code word:font-bold]
export default function Button({ size, children }) {
  let sizeClasses = {
    md: "px-4 py-2 rounded-md text-base",
    lg: "px-5 py-3 rounded-lg text-lg",
  }[size];

  return (
    <button type="button" className={`font-bold ${sizeClasses}`}>
      {children}
    </button>
  );
}
```

找到所有可能的类名后，Tailwind 会为每个类生成对应的 CSS，最终编译成只包含你真正需要的样式的样式表。

由于 CSS 是按类名生成的，Tailwind 能识别像 `bg-[#316ff6]` 这样的任意值类并生成对应的 CSS，即使该值并不在你的主题中。

更多原理参见[在源文件中检测类名](/docs/detecting-classes-in-source-files)。

### 复杂选择器

有时你需要在多个条件组合下设置元素样式，例如：在深色模式、特定断点、悬停时、且元素带有某个 data 属性时。

下面是 Tailwind 中的写法：

<CodeExampleStack>

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:dark:lg:data-current:hover:bg-indigo-600] -->
<button class="dark:lg:data-current:hover:bg-indigo-600 ...">
  <!-- ... -->
</button>
```

```css
/* [!code filename:简化后的 CSS] */
@media (prefers-color-scheme: dark) and (width >= 64rem) {
  button[data-current]:hover {
    background-color: var(--color-indigo-600);
  }
}
```

</CodeExampleStack>

Tailwind 还支持 `group-hover` 这类用法，让你在某个特定父元素被悬停时为子元素设置样式：

<CodeExampleStack>

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:group,group-hover:underline] -->
<a href="#" class="group rounded-lg p-8">
  <!-- ... -->
  <span class="group-hover:underline">Read more…</span>
</a>
```

```css
/* [!code filename:简化后的 CSS] */
@media (hover: hover) {
  a:hover span {
    text-decoration-line: underline;
  }
}
```

</CodeExampleStack>

`group-*` 语法也支持其他变体，例如 `group-focus`、`group-active` 等[更多变体](/docs/hover-focus-and-other-states#styling-based-on-parent-state)。

对于真正复杂的场景（_尤其是为你不能控制的 HTML 设置样式时_），Tailwind 支持[任意变体](/docs/adding-custom-styles#arbitrary-variants)，让你直接在类名里写任意选择器：

<CodeExampleStack>

### 何时使用内联样式

在 Tailwind CSS 项目中，内联样式仍然非常有用——尤其当数值来源于数据库或 API 这类动态来源时：

```jsx
// [!code filename:branded-button.jsx]
export function BrandedButton({ buttonColor, textColor, children }) {
  return (
    <button
      style={{
        // [!code highlight:3]
        backgroundColor: buttonColor,
        color: textColor,
      }}
      className="rounded-md px-3 py-1.5 font-medium"
    >
      {children}
    </button>
  );
}
```

对于格式化为类名后难以阅读的、非常复杂的任意值，你也可能会选择内联样式：

```html
<!-- [!code filename:HTML] -->
<!-- prettier-ignore -->
<div class="grid-[2fr_max(0,var(--gutter-width))_calc(var(--gutter-width)+10px)]"> <!-- [!code --] -->
<!-- prettier-ignore -->
<div style="grid-template-columns: 2fr max(0, var(--gutter-width)) calc(var(--gutter-width) + 10px)"> <!-- [!code ++] -->
  <!-- ... -->
</div>
```

另一种实用模式是用内联样式根据动态数据设置 CSS 变量，再在工具类中引用这些变量：

```jsx
// [!code filename:branded-button.jsx]
export function BrandedButton({ buttonColor, buttonColorHover, textColor, children }) {
  return (
    <button
      style={{
        // [!code highlight:4]
        "--bg-color": buttonColor,
        "--bg-color-hover": buttonColorHover,
        "--text-color": textColor,
      }}
      // [!code classes:bg-(--bg-color),text-(--text-color),hover:bg-(--bg-color-hover)]
      className="bg-(--bg-color) text-(--text-color) hover:bg-(--bg-color-hover) ..."
    >
      {children}
    </button>
  );
}
```

## 管理样式冲突

### 互相冲突的工具类

当你为同一个 CSS 属性添加两个类时，会以样式表中靠后的那个为准。所以在下面的例子中，元素最终会得到 `display: grid`，即便 `class` 属性里 `flex` 写在后面：

<CodeExampleStack>

```html
<!-- [!code filename:HTML] -->
<!-- prettier-ignore -->
<div class="grid flex">
  <!-- ... -->
</div>
```

```css
/* [!code filename: CSS] */
.flex {
  display: flex;
}
.grid {
  display: grid;
}
```

</CodeExampleStack>

总体而言，你不应该给同一个元素添加两个互相冲突的类——只添加你真正想生效的那个：

```jsx
// [!code filename:example.jsx]
// [!code word:gridLayout\ \?\ \"grid\"\ \:\ \"flex\"]
export function Example({ gridLayout }) {
  return <div className={gridLayout ? "grid" : "flex"}>{/* ... */}</div>;
}
```

在 React、Vue 等基于组件的库中，这通常意味着对外暴露专门用于样式定制的 props，而不是允许使用方从外部塞入额外的类，因为那些类很容易冲突。

### 使用 important 修饰符

当你确实需要强制让某个工具类生效，又没有其他办法管理优先级时，可以在类名末尾加上 `!`，让其所有声明都变为 `!important`：

<CodeExampleStack>

```html
<!-- [!code filename:HTML] -->
<!-- [!code classes:bg-red-500!] -->
<!-- prettier-ignore -->
<div class="bg-teal-500 bg-red-500!">
  <!-- ... -->
</div>
```

```css
/* [!code filename: 生成的 CSS] */
/* [!code word:!important] */
.bg-red-500\! {
  background-color: var(--color-red-500) !important;
}
.bg-teal-500 {
  background-color: var(--color-teal-500);
}
```

</CodeExampleStack>

### 使用 important 标志

如果你正在向一个已有大量高优先级 CSS 的项目中引入 Tailwind，可以在导入 Tailwind 时使用 `important` 标志，把_所有_工具类都标记为 `!important`：

<CodeExampleStack>

```css
/* [!code filename:app.css] */
/* [!code word:important] */
@import "tailwindcss" important;
```

```css
/* [!code filename:编译后的 CSS] */
/* [!code word:!important] */
@layer utilities {
  .flex {
    display: flex !important;
  }
  .gap-4 {
    gap: 1rem !important;
  }
  .underline {
    text-decoration-line: underline !important;
  }
}
```

</CodeExampleStack>

### 使用 prefix 选项

如果你的项目有类名与 Tailwind CSS 工具类冲突，可以使用 `prefix` 选项给所有 Tailwind 生成的类和 CSS 变量加上前缀：

<CodeExampleStack>

```css
/* [!code filename:app.css] */
/* [!code word:important] */
@import "tailwindcss" prefix(tw);
```

```css
  :root {
    --tw-color-red-500: oklch(0.637 0.237 25.331);
  }
}

@layer utilities {
  .tw\:text-red-500 {
    color: var(--tw-color-red-500);
  }
}
```

</CodeExampleStack>
